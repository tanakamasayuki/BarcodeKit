# MemoryUsage

> English: [README.md](README.md)

オブジェクトと符号化のメモリ量を調べるサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [MemoryUsage.ino](MemoryUsage.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<BarcodeKit.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

オブジェクトと符号化のメモリ量を調べる例です。詳細なAPIとデータの扱いは次の項目で確認します。

setupで必要な設定と最初の処理を行い、loopでは例の待機または継続処理を実行します。結果の観察と処理の終了は、下の注意点とソースの条件を対応させて確認してください。

## APIの使い方と注意点

符号化と画面への描画は別の段階です。encodeの成否を確認してから、モジュール・寸法・文字列を使います。形式ごとに許可文字・長さ・チェック桁が異なるため、文字列を設定できたこととバーコードを作れたことは別です。

整数倍率でモジュールを描き、十分なQuiet Zoneを残します。QRを画面いっぱいへ引き伸ばして正方形を崩さないようにします。M5例は設定済みの実画面が必要で、SerialPrintなら表示機器なしで符号化を試せます。

サイズ統計はその入力とオブジェクトの値で、全アプリのRAM保証ではありません。寸法・内容・描画を変えたら実際のReaderでも確認します。

## 操作と出力の見方

出力書式の一部は次のとおりです。printfの書式記号は実行時の値に変わります。表示順や数値は実行条件に応じて変わるので、その行へ進む条件と併せて確認します。

```text
 bytes buffer,
 bytes object
BarcodeKit memory, for 16 input characters where it varies
```

## 確認と問題の切り分け

オブジェクトと符号化のメモリ量を調べることを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
