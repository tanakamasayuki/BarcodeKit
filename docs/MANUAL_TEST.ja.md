# 実機での手動確認

内部の記録。日本語のみ。自動テストの範囲は [TEST_PLAN.ja.md](TEST_PLAN.ja.md)。

自動テストはホスト実行のみで、**「実際のスキャナで読めるか」だけは自動化しない**（[DECISIONS.ja.md](DECISIONS.ja.md) D7）。ここではその手順を決める。

## 1. いつ行うか

- v0.1.0 のリリース前（全形式）
- 形式を追加したとき（その形式のみ）
- 描画ヘルパーの倍率・余白の扱いを変えたとき（代表 3 形式）

## 2. 機材

| 種類 | 使うもの |
| --- | --- |
| 表示機 | M5Stack Core BASIC（320×240 TFT）。他機種で確認したら記録する |
| ホスト確認 | `lang-ship:host` コア（SDL2）で同じスケッチを実行し、画面上で見比べる |
| 読み取り | スマートフォンのスキャナアプリ、または手持ちのバーコードリーダー |

**使用したアプリ名・機種・バージョンを §5 の記録表に必ず書く。** 読めた／読めなかったの判断がアプリ依存であるため、後から追試できるようにする。

## 3. 手順

### 3.1 準備

```sh
cd examples/AllFormats
arduino-cli compile --profile m5stack_core --upload -p /dev/ttyUSB0 .
```

ボタン A で次の形式、ボタン C で前の形式に進む。画面上部に形式名・符号化後のデータ・倍率が出るので、読めなかったときはその表示ごと記録する。

### 3.2 確認項目（形式ごと）

`AllFormats` example が形式を順に表示する。各形式について以下を確認する。

| # | 確認内容 |
| --- | --- |
| 1 | 画面に収まっている（見切れていない） |
| 2 | 左右（QR は四方）に白い余白がある |
| 3 | EAN/UPC はガードバーが他のバーより下へ伸びている |
| 4 | ITF-14 はベアラバー（囲み枠）がある |
| 5 | **スキャナで読み取れる。読み取れた文字列が期待どおり** |
| 6 | **スキャナが認識した形式が期待どおり**（EAN-13 が UPC-A と誤認されていない等） |

**特に確認したいのは Codabar のチェックディジット**（`setCheckDigit(true)` を使う場合）。規格の一部ではなく運用ごとに規約が異なり、デコーダも検証しないため、**自動テストで正しさを裏付けられない唯一の箇所**になっている（[DECISIONS.ja.md](DECISIONS.ja.md) 参照）。相手システムがある場合は、その規約と一致するかをここで確かめる。

### 3.3 追加で確認すること

| 項目 | 内容 |
| --- | --- |
| 倍率 | `FitToScreen` example で、画面サイズいっぱいの倍率でも読めること |
| 最小倍率 | 倍率 1〜2 で読めるかを試し、実用下限を記録する（読めなくても不具合ではない。README に目安として書く） |
| 余白なし | `quietZone = false` で読みにくくなることを確認する（ドキュメントの主張の裏付け） |
| QR の ECC | L と H で同じ内容を表示し、どちらも読めること |
| 反射・角度 | 画面を斜めから読む、明るい場所で読むなど、実利用に近い条件で試す |

## 4. 結果の扱い

- 読めた入力と形式の組は、`tests/vectors/data/` に「実機で確認済み」のコメント付きでベクタとして固定する
- 読めなかった条件（倍率・環境）は README の注意書きに反映する
- 実装の不具合が見つかった場合は、まず**ホストの自動テストで再現するケースを書いてから**直す
